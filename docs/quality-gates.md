# Quality gates playbook — lint, full-app tests, byte-exact GUI goldens

A drop-in playbook for any repository. It sets up three gates:

1. **Lint and format** through one entry point (treefmt) wrapping ruff, prettier, a JSON validity check and a type checker.
2. **One test pipeline per app that exercises the whole app**: unit, API, front-end, and a real end-to-end scenario on the built app.
3. **GUI goldens**: every screen of every app captured as a PNG, committed, regenerated by CI and **compared byte for byte**. Any difference fails.

Everything runs in **one pinned Docker image**, locally (`just …`) and in CI, so what a developer commits is exactly
what CI regenerates.

How to use it:

- **Copy.** Put this file in `docs/quality-gates.md` and reference it from the repository's `CLAUDE.md` (snippet in §9).
- **Adapt.** Replace the placeholders:
  - `<project>`: the repository name, used for the image tag;
  - `<app>`: an app folder name in kebab-case, e.g. `web-shop`, `admin`;
  - `<App>`: its source folder.
- **Pick tools.** Keep the tool choices that match the stack: ruff for Python, prettier for CSS/YAML/Markdown,
  `tsc`/`vue-tsc` for TypeScript. The *structure* (one image, one entry point per gate, `all | tests | goldens`
  modes, byte-exact goldens, `just ci` = CI) is the part that matters.

---

## 1. Principles (non-negotiable)

**One image, one truth**

- Tests, lint and screenshots always run in the same pinned Docker image, never on the host.
- Builds are the exception: they may be native.
- The image is always built and run for **one platform**, the CI runner's (e.g. `linux/amd64`, emulated on ARM Macs).

**`just ci` = CI**

- A local recipe runs exactly the CI jobs, in the same order, in the same image.
- As long as CI is not enabled (no runner yet), `just ci` *is* the gate.

**Tests and goldens are part of every change**

- No commit with a red pipeline.
- Never disable, skip or loosen a test to get green: fix the cause.
- No `allow_failure`, no silently skipped stage. A missing tool must *fail*, not skip.

**Every app is tested end to end**

- Unit and API tests are not enough. Each app's pipeline boots the real app (real server, real built front-end, real browser or CLI), walks through every screen or command, and fails on any console or JS error.

**GUI goldens are byte-exact and committed**

- CI regenerates them and fails on any modified, deleted or new image. There is no "visual tolerance".
- Determinism is engineered: pinned fonts, renderer, clock and data (§6). It is never obtained by masking.

**Lint never modifies in check mode**

- `just lint` only reports; `just fmt` applies.
- Formatting a legacy codebase goes in its own `style:` commit, with all test pipelines re-run after it.

**Byte-pinned files are excluded from formatters**

- Design tokens, fixtures, vendored data and generated files are never reformatted.
- Data files are *validated* (e.g. JSON must parse), never rewritten.

## 3. The pinned image (`test/ci/Dockerfile`)

Pin everything that can move a pixel, a lint result or a test outcome:

- **Base image by digest.**
- **OS packages** from a dated snapshot, e.g. `snapshot.debian.org`.
- **Language packages** from a lock file installed first, then the requirements `--no-index`: the build fails if the lock is incomplete.
- **Tools** (treefmt, prettier, Playwright + Chromium) at exact versions, with checksums for downloaded binaries.
- **Fonts**, installed explicitly.

```dockerfile
# Build context: test/  (docker build --platform linux/amd64 -f test/ci/Dockerfile test)
FROM node:22-bookworm-slim@sha256:<digest>

ARG DEBIAN_SNAPSHOT=20260915T000000Z
ARG TREEFMT_VERSION=2.6.0
ARG TREEFMT_SHA256=<sha256 of the release tarball>
ARG PRETTIER_VERSION=3.9.7

ENV DEBIAN_FRONTEND=noninteractive PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 PLAYWRIGHT_BROWSERS_PATH=/ms-playwright \
    RUFF_CACHE_DIR=/tmp/ruff-cache LANG=C.UTF-8 TZ=UTC PATH=/venv/bin:$PATH

# OS packages from a fixed snapshot: same versions on every build
RUN rm -f /etc/apt/sources.list.d/debian.sources \
 && printf '%s\n' \
    "deb [check-valid-until=no] http://snapshot.debian.org/archive/debian/${DEBIAN_SNAPSHOT} bookworm main" \
    "deb [check-valid-until=no] http://snapshot.debian.org/archive/debian-security/${DEBIAN_SNAPSHOT} bookworm-security main" \
    > /etc/apt/sources.list \
 && apt-get -o Acquire::Retries=5 update \
 && apt-get -o Acquire::Retries=5 install -y --no-install-recommends \
    ca-certificates curl git python3 python3-venv \
    fonts-dejavu-core fonts-noto-core fonts-noto-color-emoji \
 && rm -rf /var/lib/apt/lists/*

# treefmt + prettier
RUN curl -fsSL -o /tmp/treefmt.tgz \
      "https://github.com/numtide/treefmt/releases/download/v${TREEFMT_VERSION}/treefmt_${TREEFMT_VERSION}_linux_amd64.tar.gz" \
 && echo "${TREEFMT_SHA256}  /tmp/treefmt.tgz" | sha256sum -c - \
 && tar -xzf /tmp/treefmt.tgz -C /usr/local/bin treefmt && rm /tmp/treefmt.tgz \
 && npm install -g --no-audit --no-fund "prettier@${PRETTIER_VERSION}" && npm cache clean --force

# Python: lock first (pinned closure), then the requirements offline (fails if the lock misses something)
RUN python3 -m venv /venv
COPY ci/requirements.lock ci/requirements.txt /tmp/ci/
COPY <app>/requirements-test.txt /tmp/<app>/requirements-test.txt
RUN pip install --no-cache-dir -r /tmp/ci/requirements.lock \
 && pip install --no-cache-dir --no-index -r /tmp/ci/requirements.txt \
 && playwright install --with-deps chromium && rm -rf /var/lib/apt/lists/*

# Playwright's deps pull GNU Unifont / FreeFont, which fontconfig then prefers for emoji: reject them
COPY ci/fonts.conf /etc/fonts/conf.d/99-screenshots.conf
RUN fc-cache -f

WORKDIR /repo
```

`test/ci/requirements.txt` aggregates the per-app files and the lint tools:


## 4. `just` recipes

```just
ci_image := env("CI_IMAGE", "<project>-ci:local")
ci_platform := "linux/amd64"

# Build (or pull) the CI image
ci-image:
    #!/usr/bin/env bash
    set -euo pipefail
    if [ -n "${CI_IMAGE:-}" ]; then docker pull --quiet --platform {{ci_platform}} "$CI_IMAGE" >/dev/null
    else docker build --quiet --platform {{ci_platform}} -t {{ci_image}} -f test/ci/Dockerfile test >/dev/null; fi

# Regenerate test/ci/requirements.lock after any requirements change
ci-lock:
    #!/usr/bin/env bash
    set -euo pipefail
    lock="$(docker run --rm --platform {{ci_platform}} -v "$PWD/test":/test:ro python:3.11-slim-bookworm sh -c \
      'pip install --quiet --root-user-action=ignore -r /test/ci/requirements.txt >&2 \
       && pip freeze --all --exclude pip --exclude setuptools --exclude wheel')"
    { echo "# Generated by just ci-lock: do not edit."; echo "$lock"; } > test/ci/requirements.lock

# Lint: every checker, nothing modified
lint: ci-image
    just _in-ci test/ci/lint.sh

# Format: apply the formatters
fmt: ci-image
    just _in-ci test/ci/lint.sh fix

# Full pipeline of one app (tests + goldens)
test APP: ci-image
    just _in-ci "test/$(just _test-dir '{{APP}}')/run-tests.sh"

# Regenerate the goldens of one app / of every app (commit them when the UI change is intended)
<app>-gui-goldens: (_gui-goldens "<app>")
all-gui-goldens: <app>-gui-goldens # other-app-gui-goldens …

# Fail if test/screenshot (or test/screenshot/<APP>) differs from HEAD
check-goldens APP="":
    test/ci/check-goldens.sh {{APP}}

# Determinism proof: regenerate RUNS times and compare the bytes
gui-goldens-stability APP RUNS="3": ci-image
    just _in-ci test/ci/goldens-stability.sh "$(just _test-dir '{{APP}}')" {{RUNS}}

# Exactly what CI runs, same image, same order (goldens are compared with HEAD: commit first)
ci: ci-image
    just _in-ci test/ci/lint.sh
    just _in-ci test/<app>/run-tests.sh tests
    just _in-ci test/<app>/run-tests.sh goldens
    test/ci/check-goldens.sh

_gui-goldens DIR: ci-image
    just _in-ci test/{{DIR}}/run-tests.sh goldens

# Run in the CI image, repo on /repo, as the host user (files never become root-owned on Linux hosts)
_in-ci +CMD:
    docker run --rm --init --platform {{ci_platform}} --user "$(id -u):$(id -g)" -e HOME=/tmp \
      -v "$PWD":/repo -w /repo {{ci_image}} {{CMD}}

# App name -> test folder; exit 2 on an unknown app
_test-dir APP:
    #!/usr/bin/env bash
    case "{{APP}}" in
      <App>|<app>) echo "<app>" ;;
      *) echo "Unknown app: {{APP}}" >&2; exit 2 ;;
    esac
```

## 5. Lint and format (treefmt)

### 5.1 `treefmt.toml`

```toml
# The single lint / format entry point.
#   just lint   checks every formatter and linter, modifies nothing (CI job "lint")
#   just fmt    applies the formatters

excludes = [
  ".git/**", "**/node_modules/**", "**/dist/**", "**/build/**", "**/__pycache__/**",
  "**/.venv/**", "**/.ruff_cache/**", "test-reports/**",
  "test/screenshot/**",          # goldens
  "package-lock.json",           # generated
  # vendored data, byte-pinned design files, legacy sources… add them here, with a reason
]
on-unmatched = "debug"

[formatter.ruff-format]
command = "test/ci/format.sh"
options = ["ruff-format"]
includes = ["*.py"]
priority = 1

[formatter.ruff-check]           # lint only, never fixes by itself
command = "ruff"
options = ["check", "--no-fix", "--output-format=concise"]
includes = ["*.py"]
priority = 2

[formatter.prettier]             # scope it to what the codebase can take without massive churn
command = "test/ci/format.sh"
options = ["prettier"]
includes = ["*.css", "*.yml", "*.yaml"]
excludes = []                    # e.g. byte-pinned token files

[formatter.json]                 # every JSON must parse; checked, never rewritten
command = "python3"
options = ["test/ci/check_json.py"]
includes = ["*.json"]

[formatter.typecheck]            # e.g. tsc --noEmit / vue-tsc --noEmit / mypy
command = "test/ci/typecheck.sh"
includes = ["*.ts", "*.vue"]
```

### 5.2 `test/ci/format.sh`: check mode never writes

```bash
#!/usr/bin/env bash
# treefmt formatter wrapper: applies a formatter, or only checks when CI_LINT_CHECK=1 (just lint).
set -euo pipefail
tool="$1"; shift
check="${CI_LINT_CHECK:-}"
case "$tool" in
  ruff-format) if [ -n "$check" ]; then exec ruff format --check --diff -- "$@"; else exec ruff format -- "$@"; fi ;;
  prettier)    if [ -n "$check" ]; then exec prettier --check -- "$@"; else exec prettier --write --log-level warn -- "$@"; fi ;;
  *) echo "format.sh: unknown formatter $tool" >&2; exit 2 ;;
esac
```

### 5.3 `test/ci/lint.sh`

```bash
#!/usr/bin/env bash
# lint.sh       check only (just lint, CI job "lint"): exit 1 on any finding, nothing modified
# lint.sh fix   apply the formatters (just fmt); linters are not run
set -uo pipefail
REPO="${REPO:-/repo}"; cd "$REPO"
case "${1:-check}" in
  check) CI_LINT_CHECK=1 treefmt --no-cache --fail-on-change ;;
  fix)   treefmt --no-cache --formatters ruff-format,prettier ;;
  *) echo "usage: lint.sh [check|fix]" >&2; exit 2 ;;
esac
```

If a type checker needs `node_modules`, install them in a copy **outside** the mounted repo (e.g. `/tmp/lint-web`):
the host's `node_modules` may hold macOS/Windows binaries and must never be touched.

### 5.4 `test/ci/check_json.py`: strict, read-only

```python
#!/usr/bin/env python3
"""treefmt linter: every given JSON file must parse as strict JSON (UTF-8, no NaN, no duplicate key). Read-only."""
import json
import sys


def no_duplicates(pairs):
    seen = {}
    for key, value in pairs:
        if key in seen:
            raise ValueError(f"duplicate key {key!r}")
        seen[key] = value
    return seen


def reject_constant(name):
    raise ValueError(f"invalid constant {name}")


def main(paths):
    failures = 0
    for path in paths:
        try:
            with open(path, encoding="utf-8-sig") as handle:
                json.load(handle, object_pairs_hook=no_duplicates, parse_constant=reject_constant)
        except (OSError, UnicodeDecodeError, ValueError) as exc:
            failures += 1
            print(f"{path}: invalid JSON: {exc}")
    return 1 if failures else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

### 5.5 `ruff.toml` (starting point)

```toml
line-length = 120
target-version = "py311"
extend-exclude = []            # vendored / data folders

[lint]
select = ["E", "W", "F", "B"]  # pycodestyle, pyflakes, bugbear — widen later, one rule set at a time
ignore = [
  "E501",                      # the formatter wraps code; long strings and comments remain
  # every other ignore needs a one-line reason, e.g. "B008" for FastAPI Depends()/File() defaults
]

[lint.per-file-ignores]
# "legacy/*.py" = ["E722"]     # narrowing bare excepts there would change behaviour
```

### 5.6 Rolling it out on an existing codebase

1. **Config commit.** Add `treefmt.toml`, `ruff.toml` and the scripts. Scope prettier and friends to file types where
   the churn is acceptable, and record why the others are out.
2. **`style:` commit.** Output of `just fmt` only, layout changes and nothing else.
3. **`fix:` / `style:` commits** for the real lint findings. Fix the real bugs (they exist: unused imports hiding
   missing ones, undefined names…). For anything else, add a per-rule ignore with a reason.
4. **Proof.** Re-run **every** app pipeline and the goldens. The style commits must change no behaviour and no pixel.

## 6. Full-app test pipeline (one per app)

### 6.1 Shared helpers: `test/ci/pipeline.sh` (sourced)

```bash
# Modes of test/<app>/run-tests.sh:
#   (none) | all   tests, then the GUI goldens
#   tests          test stages only           (CI job "test:<app>")
#   goldens        what the screenshots need + goldens (CI job "goldens:<app>", just <app>-gui-goldens)
SKIPPED=skipped
pipeline_mode() { MODE="${1:-all}"; case "$MODE" in all|tests|goldens) ;; *) echo "usage: $(basename "$0") [all|tests|goldens]" >&2; exit 2;; esac; }
runs_tests()   { [ "$MODE" != goldens ]; }
runs_goldens() { [ "$MODE" != tests ]; }
# JUnit report when PYTEST_JUNIT_DIR is set (CI)
pytest_report_args() { [ -n "${PYTEST_JUNIT_DIR:-}" ] && { mkdir -p "$PYTEST_JUNIT_DIR"; echo "--junitxml=$PYTEST_JUNIT_DIR/$1.xml"; }; }
# goldens dir, emptied first: a screen no longer captured shows up as a *deleted* golden
goldens_dir() { local d="$REPO/test/screenshot/$1"; mkdir -p "$d"; rm -f "$d"/*.png; echo "$d"; }
summary_line() { local l="$1" rc="$2" d="${3:-}"; if [ "$rc" = "$SKIPPED" ]; then printf ' %-12s: -\n' "$l"; elif [ "$rc" -eq 0 ]; then printf ' %-12s: OK%s\n' "$l" "${d:+ ($d)}"; else printf ' %-12s: FAILED (%s)\n' "$l" "$rc"; fi; }
all_ok() { local rc; for rc in "$@"; do [ "$rc" = "$SKIPPED" ] || [ "$rc" -eq 0 ] || return 1; done; }
```

### 6.2 `test/<app>/run-tests.sh`

```bash
#!/usr/bin/env bash
# <App> pipeline: pytest (unit + API + integration), front-end tests + build, end-to-end scenario + GUI goldens.
set -uo pipefail
REPO="${REPO:-/repo}"
WEB_BUILD="${WEB_BUILD:-/tmp/<app>-web}"     # front built OUTSIDE the mounted repo
source "$REPO/test/ci/pipeline.sh"
pipeline_mode "${1:-}"
cd "$REPO/test/<app>"
PYTEST_RC=$SKIPPED WEB_RC=$SKIPPED E2E_RC=$SKIPPED E2E_DETAIL=""

if runs_tests; then
  python -m pytest -q --color=no -p no:cacheprovider $(pytest_report_args "<app>")
  PYTEST_RC=$?
fi

# front-end: always built (the e2e scenario needs it); unit tests only in "tests"/"all"
rsync -a --delete --exclude node_modules --exclude dist "$REPO/<App>/web/" "$WEB_BUILD/"
( cd "$WEB_BUILD" && npm ci --no-audit --no-fund --loglevel=error \
  && { ! runs_tests || npx vitest run; } && npm run build )
WEB_RC=$?

if runs_goldens; then
  SHOTS="$(goldens_dir <app>)"
  if [ $WEB_RC -eq 0 ]; then
    APP_STATIC="$WEB_BUILD/dist" python screenshots.py "$SHOTS"   # end-to-end scenario + captures
    E2E_RC=$?
  else
    E2E_RC=1
  fi
  E2E_DETAIL="$(ls -1 "$SHOTS"/*.png 2>/dev/null | wc -l | tr -d ' ') images"
fi

summary_line pytest "$PYTEST_RC"; summary_line front "$WEB_RC"; summary_line e2e "$E2E_RC" "$E2E_DETAIL"
all_ok "$PYTEST_RC" "$WEB_RC" "$E2E_RC"
```

### 6.3 What "tests the whole app" means

Each app's pipeline must include, at minimum:

- **Unit tests** of the business logic, with no UI and no I/O mocks where the real thing is cheap.
- **API tests** against the real app object (e.g. FastAPI `TestClient`): every route, including its error paths, with messages asserted **verbatim**.
- **Front-end tests** (vitest or similar), including verbatim text assertions for user-facing strings.
- **An end-to-end scenario on the built app.** Start the real server in-process on a free port, with seeded data (a copy of a fixture DB, a fixed temp folder), serve the **built** front-end, and drive it in headless Chromium through **every screen, dialog and error state**. The scenario:
  - fails on any `pageerror` or console error, and on any missing expected element;
  - asserts key behaviours (browser checks), not only pixels;
  - writes the GUI goldens at each state (§7).
- **For non-GUI tools:** the same idea with the real CLI or entry point on fixture inputs, and the outputs compared to committed expectations.
- **Structural guards where relevant**, e.g. a test that scans the source for forbidden imports.

## 7. GUI goldens: byte-exact screenshots

### 7.1 Determinism checklist

Every item below has broken byte-identity at least once in practice.

| Source of noise | Fix |
|---|---|
| Different Chromium / fonts / libs between machines | One pinned image, one platform (`linux/amd64`, even on ARM Macs via emulation) |
| GPU / LCD / hinting / CPU-specific Skia paths | Chromium flags (below): software rendering, no LCD text, no hinting, sRGB, `--disable-skia-runtime-opts` |
| CSS transitions / animations caught mid-way | Injected style sheet (`transition/animation: none`), plus `settle()` waiting for `document.getAnimations()` to finish |
| Caret blink, smooth scroll, scrollbars | `caret-color: transparent`, `scroll-behavior: auto`, `--hide-scrollbars` |
| Wall-clock time on screen | Playwright `page.clock.set_fixed_time(...)`; freeze the backend clock too (inject a clock, or a virtual clock in the harness) |
| Live / simulated data (sensors, random, timers) | Seeded fakes on a **virtual clock** that only advances when the scenario says so; wait until the page shows the backend state |
| Random temp paths printed on screen | Fixed folder names for the scenario's data |
| Filesystem listing order | Sort in the scenario, or create inputs in a fixed order; record it as a known risk if the order comes from code you can't change |
| Race between async responses (e.g. an SSE event arriving before a POST answer) | Fix the app: the stability run finds real bugs |
| Viewport, DPR, locale, time zone, colour scheme | Fixed browser context (below) |
| PNG metadata (dates, gamma, text chunks, encoder settings) | Re-encode every PNG from its pixels with a fixed encoder (`encode_png` below) |
| Emoji rendered as monochrome glyphs or boxes | `fonts-noto-color-emoji` plus fontconfig rejecting Unifont/FreeFont (§3) |
| Host-owned vs root-owned files | Run the container with `--user "$(id -u):$(id -g)"` |

### 7.2 `test/ci/golden.py`: the shared capture helpers

```python
"""Deterministic GUI captures shared by every screenshot script (Playwright, sync API)."""
import io
import struct
import zlib
from datetime import datetime, timezone
from pathlib import Path

GOLDEN_TIME = datetime(2026, 1, 15, 9, 30, 0, tzinfo=timezone.utc)
LOCALE = "fr-FR"
TIMEZONE = "Europe/Paris"

CHROMIUM_ARGS = [
    "--disable-gpu", "--disable-gpu-compositing", "--disable-accelerated-2d-canvas",
    "--disable-lcd-text", "--font-render-hinting=none", "--disable-font-subpixel-positioning",
    "--force-color-profile=srgb", "--disable-skia-runtime-opts", "--disable-smooth-scrolling",
    "--disable-partial-raster", "--disable-threaded-animation", "--disable-threaded-scrolling",
    "--disable-checker-imaging", "--disable-image-animation-resync", "--hide-scrollbars",
    "--mute-audio", "--no-first-run",
]

FREEZE_CSS = """
*, *::before, *::after {
  transition: none !important; animation: none !important;
  caret-color: transparent !important; scroll-behavior: auto !important;
}
"""

_INJECT_CSS = """((css) => {
  const add = () => {
    if (document.querySelector('style[data-golden]')) return
    const s = document.createElement('style'); s.setAttribute('data-golden', ''); s.textContent = css
    ;(document.head || document.documentElement).appendChild(s)
  }
  if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', add); else add()
})"""


def launch(playwright):
    return playwright.chromium.launch(args=CHROMIUM_ARGS)


def new_page(browser, viewport, now=GOLDEN_TIME):
    context = browser.new_context(viewport=viewport, device_scale_factor=1, locale=LOCALE,
                                  timezone_id=TIMEZONE, color_scheme="light")
    context.add_init_script(f"{_INJECT_CSS}({FREEZE_CSS!r})")
    page = context.new_page()
    if now is not None:
        page.clock.set_fixed_time(now.timestamp() if isinstance(now, datetime) else now)
    return page


def settle(page):
    """Web fonts loaded, no running animation, two rendered frames."""
    page.evaluate("document.fonts.ready.then(() => undefined)")
    page.wait_for_function("() => document.getAnimations().every((a) => a.playState !== 'running')")
    page.evaluate("() => new Promise((r) => requestAnimationFrame(() => requestAnimationFrame(r)))")


def screenshot(target, path):
    data = target.screenshot(animations="disabled", caret="hide", scale="css")
    write_png(path, data)
    return Path(path)


def write_png(path, data):
    from PIL import Image
    with Image.open(io.BytesIO(data)) as image:
        image.load()
        Path(path).write_bytes(encode_png(image))


def encode_png(image):
    """PNG bytes depending only on the pixels: RGB(A) 8-bit, "Up" filter, zlib level 9, no ancillary chunk."""
    from PIL import Image, ImageChops
    has_alpha = "A" in image.getbands() and image.convert("RGBA").getextrema()[3][0] < 255
    image = image.convert("RGBA" if has_alpha else "RGB")
    width, height = image.size
    above = Image.new(image.mode, image.size)
    above.paste(image.crop((0, 0, width, height - 1)), (0, 1))
    filtered = ImageChops.subtract_modulo(image, above).tobytes()
    stride = width * len(image.getbands())
    rows = b"".join(b"\x02" + filtered[y * stride:(y + 1) * stride] for y in range(height))

    def chunk(tag, payload):
        return struct.pack(">I", len(payload)) + tag + payload + struct.pack(">I", zlib.crc32(tag + payload))

    return (b"\x89PNG\r\n\x1a\n"
            + chunk(b"IHDR", struct.pack(">IIBBBBB", width, height, 8, 6 if has_alpha else 2, 0, 0, 0))
            + chunk(b"IDAT", zlib.compress(rows, 9))
            + chunk(b"IEND", b""))
```

### 7.3 Screenshot script skeleton (`test/<app>/screenshots.py`)

```python
"""End-to-end scenario on the built app + GUI goldens. Usage: screenshots.py OUT_DIR"""
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "ci"))
import golden  # noqa: E402
from playwright.sync_api import expect, sync_playwright  # noqa: E402


def main(out_dir: Path) -> int:
    base = start_local_server_on_fixture_data()   # real app, seeded copy of the data, fixed paths, built front
    errors = []
    with sync_playwright() as p:
        browser = golden.launch(p)
        page = golden.new_page(browser, {"width": 1280, "height": 820})
        page.on("pageerror", lambda e: errors.append(f"pageerror: {e}"))
        page.on("console", lambda m: m.type == "error" and errors.append(f"console: {m.text}"))

        def shot(name):
            golden.settle(page)
            golden.screenshot(page, out_dir / f"{name}.png")

        page.goto(base)
        expect(page.get_by_role("heading", name="…")).to_be_visible()   # browser check
        shot("01-home")
        page.get_by_role("button", name="…").click()
        expect(page.get_by_role("dialog")).to_be_visible()
        shot("02-confirm-dialog")
        # … every screen, dialog, empty state, error state …
        browser.close()
    for e in errors:
        print(e)
    return 1 if errors else 0


if __name__ == "__main__":
    sys.exit(main(Path(sys.argv[1])))
```

Naming: use a two-digit prefix in scenario order plus a short state name. Captures are the scenario's evidence,
so a reviewer can walk the app from the file list alone.

### 7.4 `test/ci/check-goldens.sh`

```bash
#!/usr/bin/env bash
# Fails when test/screenshot (or test/screenshot/APP) differs from HEAD: modified, deleted or new files.
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
target="test/screenshot${1:+/$1}"
changes="$(git status --porcelain --untracked-files=all -- "$target")"
if [ -n "$changes" ]; then
  echo "✗ GUI goldens differ from the commit ($target):"; echo "$changes"
  echo "Intended UI change: just ${1:-all}-gui-goldens, review the images, commit them. Otherwise: regression."
  exit 1
fi
echo "✓ GUI goldens identical to the commit ($target)"
```

### 7.5 `test/ci/goldens-stability.sh`

```bash
#!/usr/bin/env bash
# Regenerates an app's goldens RUNS times and compares the SHA-256 of every PNG with run 1. Exit 1 on any difference.
set -uo pipefail
APP="${1:?usage: goldens-stability.sh APP [RUNS]}"; RUNS="${2:-3}"
REPO="${REPO:-/repo}"; DIR="$REPO/test/screenshot/$APP"; WORK="$(mktemp -d)"
for run in $(seq 1 "$RUNS"); do
  "$REPO/test/$APP/run-tests.sh" goldens > "$WORK/run$run.log" 2>&1 || { tail -40 "$WORK/run$run.log"; exit 1; }
  (cd "$DIR" && sha256sum -- *.png) > "$WORK/run$run.sha256"
done
status=0
for run in $(seq 2 "$RUNS"); do
  diff "$WORK/run1.sha256" "$WORK/run$run.sha256" && echo "run $run: identical" || { echo "run $run: DIFFERENT"; status=1; }
done
exit $status
```

### 7.6 Workflow

- **Intended UI change:**
  1. `just <app>-gui-goldens`;
  2. look at every changed image (`git diff --stat test/screenshot`, then open them);
  3. commit them with the change, and list in the commit body which captures changed and why.
- **New screen or state:**
  1. extend the app's screenshot script through `golden.py`;
  2. prove determinism with `just gui-goldens-stability <app> 3`;
  3. commit.
- **Unexpected diff:** treat it as a regression until proven otherwise.
  - If a capture flips between identical runs, fix the source of noise (§7.1).
  - Never exclude the capture, and never raise a tolerance.
- **Other apps sharing a component:** after changing shared UI code, run *every* app's goldens. Unchanged apps must stay byte-identical.
- **Optional:** dump the DOM of key states (attributes compared as sets) to explain pixel diffs in reviews.

## 8. CI

The pipeline mirrors `just ci` and runs every job **directly in the CI image**: no Docker-in-Docker.

- **Stages:** `image` → `lint` → `test:<app>` (one job per app, `run-tests.sh tests`) → `goldens:<app>` (`run-tests.sh goldens`, then `check-goldens.sh <app>`).
- **Image job:** build `test/ci/Dockerfile` for the runner's platform and push it to the registry, tagged with the commit SHA. With GitLab, use Kaniko (or buildah or rootless BuildKit), pinned by digest. Registry layer cache.
- **Artifacts:**
  - test jobs keep a JUnit report and the full log, `when: always`;
  - golden jobs upload the regenerated `test/screenshot/<app>/`, `when: on_failure`, so the diff can be inspected.
- **No failures allowed:** no `allow_failure` on tests, lint or goldens.
- **Caches:** read in every job, written by a single job, so parallel jobs never race.
- **Kill switch:** while no runner exists, gate the whole pipeline on a project variable, so pushes don't leave pending pipelines:

  ```yaml
  workflow:
    rules:
      - if: $CI_ENABLED != "true"
        when: never
      - if: $CI_PIPELINE_SOURCE == "merge_request_event"
      - if: $CI_COMMIT_BRANCH && $CI_OPEN_MERGE_REQUESTS
        when: never
      - if: $CI_COMMIT_BRANCH
      - if: $CI_COMMIT_TAG
  ```

- **Minimal GitLab job shape:**

  ```yaml
  default:
    image: $CI_REGISTRY_IMAGE/ci:$CI_COMMIT_SHA

  .test:
    stage: test
    needs: [ci-image]
    script:
      - mkdir -p test-reports && set -o pipefail
      - REPO="$CI_PROJECT_DIR" PYTEST_JUNIT_DIR="$CI_PROJECT_DIR/test-reports" "test/$APP/run-tests.sh" tests 2>&1 | tee "test-reports/$APP.log"
    artifacts: { when: always, paths: [test-reports/], reports: { junit: test-reports/*.xml } }

  .goldens:
    stage: goldens
    needs: [ci-image]
    script:
      - REPO="$CI_PROJECT_DIR" "test/$APP/run-tests.sh" goldens
      - test/ci/check-goldens.sh "$APP"
    artifacts: { when: on_failure, paths: ["test/screenshot/$APP/"] }
  ```

- **GitHub Actions:** same jobs with `container: image: ghcr.io/<owner>/<project>-ci:${{ github.sha }}` after a job that builds and pushes it.
- **First pipeline on a real runner:** it is the first proof of byte-identity on that CPU. Goldens proven only under emulation on a developer Mac can differ on the runner. If they do on an unchanged UI, fix the renderer settings. Only as a last resort, and as an explicit decision, make the CI's images the reference.

## 11. Pitfalls seen in practice

- **ARM Mac, amd64 CI:** always pass `--platform linux/amd64` to `docker build` and `docker run`. Mixing platforms gives different pixels.
- **A stability run finding a flaky golden** usually means a real race in the app, e.g. an event stream answering before the HTTP response. Fix the app, not the test.
- **Transitions:** a screenshot of an element "just clicked" catches hover or focus transitions. `settle()` plus the frozen style sheet fixes it.
- **Host `node_modules` in the mounted repo:** never install or build inside `/repo` from the container. Copy the web workspace to `/tmp` and build there.
- **Root-owned files after a container run** (Linux hosts): run the container as the host user.
- **A formatter touching byte-pinned files** (design tokens, fixtures) silently breaks contracts. Exclude them explicitly in `treefmt.toml`.
- **HTML formatting can change rendered text**, e.g. collapsing double spaces in `<title>`. Keep HTML out of prettier unless every page is checked.
- **Lock drift:** installing the lock first and then the requirements with `--no-index` makes an incomplete lock fail the image build, instead of silently resolving new versions.
- **Tests that `importorskip` a tool** in CI silently lose coverage. Import it plainly, so a missing tool fails.
